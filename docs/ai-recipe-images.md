# AI φωτογραφίες συνταγών — προετοιμασία, Οκτώβριος 2026

## Τρέχουσα κατάσταση

Η λειτουργία είναι απενεργοποιημένη από προεπιλογή. Η προετοιμασία βρίσκεται σε ξεχωριστό branch/PR και δεν αλλάζει το production site. Δεν έχει ενεργοποιηθεί billing, δεν προστέθηκαν secrets και δεν έγινε πραγματική κλήση δημιουργίας εικόνας.

Όταν ενεργοποιηθεί με νέα έγκριση, οι κάρτες και οι λεπτομέρειες συνταγής θα φορτώνουν μία AI εικόνα του τελικού πιάτου βάσει τίτλου, περιγραφής, υλικών, επιπλέον υλικών και βημάτων. Η εικόνα έχει ένδειξη `AI image`: είναι ενδεικτική, όχι φωτογραφία πραγματικού μαγειρεμένου αποτελέσματος. Η εφαρμογή παραμένει αγγλόφωνη, όπως ήδη είναι.

## Ασφαλής ενεργοποίηση — όχι τώρα

Πριν ενεργοποιηθεί χρειάζονται νέα έγκριση κόστους, επιλογή ημερήσιου ορίου, Google project με ενεργή χρέωση και ελεγχόμενη live δοκιμή. Δεν αρκεί το υπάρχον δωρεάν Gemini key για κείμενο.

Τα παρακάτω είναι server-only μεταβλητές Netlify, ΟΧΙ VITE_*:

- `AI_RECIPE_IMAGES_ENABLED`: πρέπει να είναι ακριβώς `true`. Αν λείπει ή είναι `false`, δεν καλείται το image API. Δεν προστέθηκε ούτε άλλαξε στη διαδικασία προετοιμασίας.
- `GEMINI_IMAGE_API_KEY`: ξεχωριστό key για ελεγχόμενο, billing-enabled Google project. Δεν επαναχρησιμοποιείται αυτόματα το `GEMINI_API_KEY`. Εισαγωγή μόνο ιδιωτικά στο Netlify, ποτέ σε chat, git ή browser code.
- `AI_RECIPE_IMAGES_DAILY_LIMIT`: απαιτείται ρητός ακέραιος από 1 έως 1000. Αν λείπει/είναι 0/είναι μη έγκυρος, δεν γίνεται δημιουργία. Δεν ορίστηκε όριο στην προετοιμασία.

Πρώτα μόνο deploy-preview context. Απαιτείται δοκιμή μίας εικόνας με νέο consent για χρεώσιμη κλήση, έλεγχος κόστους στο Google, έλεγχος Netlify Blobs runtime context και αποθήκευσης, και έπειτα νέα έγκριση για merge/production. Απουσία πληρωμένης live δοκιμής σημαίνει ότι η πραγματική εικόνα, ποιότητα, χρόνος και storage integration δεν έχουν επαληθευθεί end-to-end.

## Κόστος και όρια

Το μοντέλο είναι `gemini-3.1-flash-lite-image` με οριζόντια 16:9 εικόνα 1K. Η επίσημη τιμή στις 8 Οκτωβρίου 2026 είναι περίπου $0.0336 ανά εικόνα, συν input tokens. Τα όρια μετρούν απόπειρες κλήσεων ανά UTC ημέρα σε όλο το site, όχι ακριβές χρηματικό ποσό. Για παράδειγμα, 30 απόπειρες/ημέρα αντιστοιχούν περίπου σε $1.01 μόνο για επιτυχείς εικόνες, χωρίς να αποτελούν εγγυημένο ανώτατο ποσό χρέωσης. Αποθήκευση/reads/bandwidth στο Netlify ακολουθούν τα όρια και τις χρεώσεις του εκάστοτε πλάνου. Δεν ενεργοποιείται ούτε αναβαθμίζεται κάποιο πλάνο από τον κώδικα.

Απαιτούνται επίσης έλεγχοι quotas/budgets στο Google και παρακολούθηση χρήσης στο Netlify. Τα Google budget alerts από μόνα τους δεν είναι hard spending caps.

## Αποθήκευση και επαναχρησιμοποίηση

- Οι εικόνες αποθηκεύονται σε site-wide Netlify Blobs store `fridgie-ai-recipe-images-v1` ως JSON με base64 image data. Μέγιστο image payload 2 MB. Δεν στέλνεται η φωτογραφία ψυγείου στο image API, μόνο κείμενο συνταγής.
- Το SHA-256 κλειδί περιλαμβάνει μοντέλο, version, τίτλο, περιγραφή, υλικά και βήματα. Η ίδια συνταγή επαναχρησιμοποιεί την αποθηκευμένη εικόνα· διαφορετική παρασκευή παίρνει διαφορετικό κλειδί.
- Atomic `onlyIfNew` reservations αποτρέπουν διπλές χρεώσεις για ταυτόχρονες ίδιες συνταγές. Atomic ημερήσια slots αποτρέπουν υπέρβαση αριθμού κλήσεων μεταξύ διαφορετικών Function instances.
- Deploy previews μοιράζονται site-wide stores με production. Δεν ενεργοποιούμε ανεξέλεγκτα generation σε previews.
- Δεν γίνεται αυτόματο retry. Αποτυχημένες ή αβέβαιες κλήσεις κρατούν reservation και καταναλώνουν ημερήσιο slot. Χρειάζεται έλεγχος χρέωσης από διαχειριστή πριν καθαριστεί ένα `failed`/`pending` reservation. Εξαντλημένο ημερήσιο όριο δεν καλεί τον πάροχο και ελευθερώνει την κράτηση της συνταγής.
- Δεν μπαίνουν μεγάλα AI image bytes στο localStorage. Η server cache εξυπηρετεί επαναφόρτωση/αγαπημένα. Οι υπάρχουσες stock φωτογραφίες διατηρούν την αρχική συμπεριφορά όταν η AI λειτουργία είναι κλειστή.
- Αν η δημιουργία αποτύχει, εμφανίζεται η υπάρχουσα εικονογράφηση χωρίς να εμποδίζεται η συνταγή.
- Οι quotas είναι συνολικά για το site, όχι ανά άτομο. Πριν από μεγάλη δημόσια προώθηση χρειάζεται πρόσθετη προστασία από κατάχρηση: η εφαρμογή δεν έχει authentication και ένας τρίτος μπορεί να εξαντλήσει το ημερήσιο image quota. Ο κώδικας είναι προετοιμασία, όχι πλήρης anti-abuse λύση.
- Εικόνες και quota records χρειάζονται μελλοντική πολιτική retention/cleanup για να μην αυξάνεται η αποθήκευση επ' αόριστον. Δεν διαγράφονται αυτόματα στην προετοιμασία.

## Απενεργοποίηση

Θέστε `AI_RECIPE_IMAGES_ENABLED=false` και κάντε νέο deploy. Δεν γίνονται νέες image API κλήσεις. Ήδη εμφανισμένες/αποθηκευμένες εικόνες και ήδη εν εξελίξει αιτήματα δεν αναιρούνται με αλλαγή μεταβλητής.
